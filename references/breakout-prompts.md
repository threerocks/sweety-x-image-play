# 主体出框：真假分栏共用一个等宽网格

## 先区分三件事

- 视觉栏：观众看到的窄栏。真实栏与模拟栏必须同宽、同间距。
- 实际附件：上传的 PNG。主图附件可以容纳多个视觉栏，所以附件宽度不必相同。
- 主体选区：需要完整呈现并遮住模拟栏缝的对象。真实附件切口不得穿过它。

默认规划 20 个视觉栏，不是硬切 20 个附件。实际附件数量由主体占栏数决定，最多 20 张。连续切片模式仍可输出 20 个等宽附件，但不能将其直接套用到主体出框。

## 1. 分析与布局提示词

```text
分析原图，为“主体区域模拟分栏、外围区域真实分栏”制定方案。
用户重点：{用户指定；未指定则根据图像判断}。

列出 target（主角）、exclude（非主角）、occlusion（原图遮挡关系）与 text（文字内容及位置）。接触、抓握、承托或遮挡不代表属于同一个主角。石头为主角时只选石头，不选手；猫为主角时不自动包含叶片、花盆和墙面。

在完整画面上建立统一网格：{column_count=20} 个视觉栏，每栏可见内容宽 {column_width=80} px，栏缝 {gap_width=8} px。总宽 = 栏数×栏宽 + (栏数−1)×缝宽。先等比准备母图，保持主体比例。

找出覆盖主体横向范围的最少连续整栏，合并为一个宽附件。此附件内模拟分栏，主体跨过的是内部模拟缝。其余外围栏各导出一个独立窄附件，以平台间隙形成真实分栏。真实切口必须避开全部需要完整呈现的主体及轮廓细节。

宽附件包含 k 栏时，其宽度为 k×栏宽+(k−1)×缝宽。两边窄附件均为一栏宽。禁止按剩余空间随意分配侧条宽度，禁止宽主图内外使用两套节距。

报告视觉栏数、主图占哪几栏、实际附件数及每张宽度。若主体覆盖整幅宽度，说明无法同时保留主体完整和外围真实分栏，不能擅自切开主体或宣称混合效果已实现。若用户明确要求实际上传恰好 20 张，应重新规划更多视觉栏并检查构图，而不是将主体拆成 20 份。
```

## 2. 主体蒙版提示词

```text
输入原图，输出与完整画布精确对齐的灰度蒙版。
目标：{target}；排除：{exclude}；遮挡：{occlusion}。

白色只标记目标实际可见表面，其他区域为黑色。保持原位置、大小、比例与朝向；不补画被手、叶片或墙遮住的目标。目标内部实心白色，眼睛、黑毛、纹理、阴影不能变成黑洞。不得新增原图不可见的耳朵或肢体。

本蒙版仅负责主角识别，不包含标题保护矩形，不为了消除短白线而把手或叶片并入主角。完成后叠回原图验收主体选择、位置与边界。
```

## 3. 合成提示词

```text
按已经确定的同一网格制作真假分栏混合效果。

宽主图内：背景模拟等宽分栏，主体可以自然遮住内部栏缝，使主体保持完整。外围：一栏一个真实附件，不再额外画一套竖缝，不在真实接缝处烘焙透明边，避免双重间距。

“线不能乱断”指栏缝在背景中要连续，同一条缝保持固定横坐标、宽度和节奏；被主角遮挡是出框效果本身，不是要求线穿透主角。不能把这句话解释成所有线必须贯穿主体全高。

处理短线和伪遮挡：拇指不能被当作石头，但也不能忽略其遮挡关系，把孤立短白线当作合格效果。检查同一栏缝的完整可见路径；出现悬空短段时调整该模拟缝的可见范围或整体布局，保持语义主角蒙版不变，记录视觉修正，不通过扩大主角选区吞并手或植物。

海报：不能用一个完整标题保护矩形盖掉顶部所有模拟缝，导致线从标题下沿突然开始。标题内容保留，标题所在背景继续遵守同一分栏网格；主图里的猫正常遮挡模拟缝。真实切口仍不能切过猫。

保留原图作为固定颜色与纹理层，生成选区不等于重绘主体。宽主图必须作为一个文件导出，内部模拟栏绝不能再次切成独立附件。
```

## 4. 交付验收提示词

```text
必须用最终实际附件做带间距预览，不能只交付零间距母图证明“主体完整”。

检查：
1. 主体横跨模拟缝，但整个位于同一个真实附件内；真实切口没有穿过脸、石头、手势等目标。
2. 主图内部每个模拟栏与外围真实窄栏宽度一致；所有附件按同一显示高度等比显示，不能将宽附件压到窄附件宽度。
3. 模拟缝与真实附件间距在目标显示比例下匹配。文件像素中的缝宽需要按显示缩放换算，不能直接假设等于客户端 CSS 像素。
4. 真实附件边缘没有额外烘焙的缝，模拟栏中没有拇指短白线、眼部黑洞或标题下沿突然起线。
5. 数量、宽高、顺序、透明度、来源区间及带缝重组通过检查；实际上传附件数单独报告。

平台显示比例和间距未经实测时明确标注本地模拟。平台若采用不同缩放/裁切，必须根据实际预览调整；不能把机械检查当成发布效果通过。
```

执行使用 `layout: hybrid`，具体参数见 [导出方案](export-plans.md)。旧 `uniform` 是每个附件等宽，旧 `adaptive` 是自由分配附件宽度，都不能作为本玩法的默认路径。

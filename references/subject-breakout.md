# 主体出框：依据原图决定突出什么

适用于“背景像被切成条，主体却伸到条框前面”的多图效果。参考帖只说明机制，不规定人物、动作、附件数量和主体位置。

## 从图像中选前景

先看整幅原图，用一句话说明突出哪个动作或形状，以及观众首先会看哪里。优先依据用户指定重点；没有指定时，从动作关系、近大远小、自然轮廓和留白判断。不要将几何中心、高亮区域或人脸检测框直接当成前景蒙版。

| 输入图像的线索 | 可选择的重点 | 应保留的联系 |
|---|---|---|
| 人物端碗、递花、展示物件 | 朝镜头伸出的物件，连同抓握它的手 | 指尖、物件边缘、手腕；保护人脸辨识区域 |
| 宠物探头、伸爪或甩尾 | 头、爪、尾巴中最能说明动作的部分 | 关节与身体连接，不做悬浮断肢 |
| 侧置产品、植物或建筑 | 产品轮廓、花枝、屋檐等有纵深的结构 | 商标、花瓣边缘或轮廓，不强行加入人物 |
| 横向动作、多个相互作用主体 | 动作两端与必要的连接部位 | 保持朝向与互动关系；可能需要更宽的主附件 |
| 主体贴边、铺满画面或轮廓难分 | 先评估是否还能留下背景条缝 | 不能为了玩法改脸、拉长肢体或抹掉主体；必要时减少附件或建议其他模式 |

这些是选择依据，不是必须照做的类别映射。人脸不必总是完整“跳出”，但五官不应被真实附件缝意外截断。突出区域不宜铺满全图，否则前后层次会消失。

## 三种边界必须区分

1. **前景轮廓**：用原图同尺寸的灰度蒙版描述。白色=完整保留原图像素，黑色=背景可以被条缝遮去，灰色=抗锯齿过渡。透明蒙版区域按黑色处理。主体蒙版不是一张重新生成的人像。
2. **图内条缝**：背景通过 Alpha 透明消失，前景覆盖部分条缝，形成前后遮挡。条宽、间距、圆角依据画面尺度设置，不能固定照搬参考数值。不要填白色冒充透明。
3. **实际附件分界**：由 X 排列并产生真实间距，无法被前景“跨附件覆盖”。把需连续保留的前景范围放在一张宽附件内，剩余背景切为若干窄片。主附件可以在左侧、中间、右侧，不强制对称。

## 制作与动态布局

- 查看原图后选定前景。使用可用的抠图/分割工具或内置图像编辑生成蒙版；必要时修正细边。原图作为固定像素层，只把蒙版用于合成，不把重绘主体当原图保真。
- 若工具输出主体透明抠图，只提取其 Alpha 作为蒙版，并核对尺寸、位置与原图一致。不要直接把 RGB 抠图当灰度蒙版。
- 写一条制作说明：突出对象及理由、哪些部位保持连续、为何选当前数量。固定模板不代替这项图像判断。
- `breakout` 导出器从非零蒙版范围计算主附件的横向保护范围，按左右剩余空间分配窄片。`subject_padding` 与 `min_panel_width` 可调整。显式 `widths` 用于人工精调；总宽必须等于原图宽，切口不能穿过保护范围。
- 多个前景相距很远时，保护范围包含它们之间的区域。这是保持其连续性的保守选择，不代表自动分割出多个独立主体。如需不同分组，应先规划构图，不让脚本猜测。
- 过细的虚线、半透明玻璃、复杂发丝或蒙版边缘噪声必须人工目视。非零的孤立蒙版噪点也会影响主附件范围，应先修蒙版，不靠裁切隐藏问题。

导出示例见 [参数说明](export-plans.md#主体出框)。最终交付逐张尺寸与透明 PNG；`foreground_pixels_preserved` 只验证白色蒙版区域像素未变，不能证明蒙版选对了主体。附件排列、暗色主题及压缩是否保留透明仍以目标 X 客户端为准。

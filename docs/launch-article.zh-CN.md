# 用 AI 做 X 连续长图与窄条切片：开源 Skill `sweety-x-image-play` 发布

在 X 上刷到过横贯时间线、能一路向右滑的拼接长图，或者几根细长物件并排立在帖子里吗？把一张完整画面拆成多张图按顺序上传，能做出很强的视觉延伸感；但真要自己动手做，光靠给 AI 写提示词往往会卡在尺寸和接缝上。

为了把这类多图玩法变成可重复、可核验的日常工作流，我把整套流程整理成了一个开源 Skill `sweety-x-image-play`，现已发布在 GitHub：[https://github.com/threerocks/sweety-x-image-play](https://github.com/threerocks/sweety-x-image-play)。它由面向 AI 助手的 Skill 规范与本地确定性 Python 脚本组成：AI 负责构图规划与生成母图，脚本负责精确像素裁切、排序打包与结果校验。在依赖齐全、助手支持生图的环境中，你可以用自然语言说明玩法、张数与目标尺寸，让助手完成制作；如果手里已有画好的横图，也可以跳过生图步骤，直接交由脚本完成切片。

## 先看实际效果

下面展示的是仓库自带的拼图预览效果。需要说明的是，预览图为了方便在发帖前核对横向连接关系，人为加入了模拟间距；真正导出给你用来上传的，是一组按顺序编号的独立 PNG 图片以及对应的压缩包。

![云海列车：20 张连续切片的拼图预览](https://raw.githubusercontent.com/threerocks/sweety-x-image-play/main/examples/mountain-train/preview.png)

仓库目前收录了三组原创实测案例：**云海列车**、**机器人与猫咪**和**云中游龙**。这三组案例均采用连续切片模式制作：先通过内置生图工具绘制 `1536×1024` 的母图，左右各裁掉 8 像素得到 `1520×1024`，再竖向均分为 20 张 `76×1024` 切片，全程没有任何拉伸或挤窄，三组共计生成 60 张独立图片。

![机器人与猫咪：20 张连续切片的拼图预览](https://raw.githubusercontent.com/threerocks/sweety-x-image-play/main/examples/robot-cat/preview.png)

## 为什么不能只靠写提示词

如果直接让图像模型生成 20 张首尾相接的 `76×1024` 竖图，提示词不能保证精确尺寸或相邻图连续：单张像素宽高容易对不上、相邻边缘线条错位、主体比例走形，甚至连输出顺序都会弄乱。

`sweety-x-image-play` 的思路是把创作与像素计算拆开，先生成完整母图或独立素材，再按精确坐标切分，从流程上减少返工。同时也要留意，连续裁切保证母图像素关系，但界面缝隙仍可能打断细节。数量多本身并不决定效果，先想清楚读者为什么要向右滑动再决定拆成几张，通常比盲目拉满二十张更耐看；构图时让铁轨、桥梁、绳索或龙身穿过图片间隙会很自然，而把普通人像切分过多，五官很容易正好落在客户端缝隙里被切开。

围绕常见的 X 多图互动形式，这个 Skill 梳理了三种玩法，导出脚本支持 **2–20 张**切片，每张尺寸由具体方案决定：

1. **独立窄条 `independent`**：适合充电线、铅笔、竹子或饼干棒这类细长物体。每个主体单独出图，保留两端原有比例，只拉长明确指定的中段区域。比如 2026 年 11 月 12 日在时间线上观察到的 [mamintzz 四张 Pocky 窄条帖子](https://x.com/mamintzz/status/2120786097701842965)，当时读取到的 4 张图片均为 `40×1920`；这是加载版本的尺寸，不一定等于作者上传原尺寸；在方案中也能按题材配置其他张数和比例。
2. **连续切片 `panorama`**：适合列车、游龙、长卷山水等横贯画面的场景。先完成整幅母图，再由脚本按坐标等宽竖切，仓库现有的三组原创实测案例均基于这一模式制作。
3. **横滑揭晓 `reveal`**：适合“绳子另一头连着谁”或“手臂碰到了谁”这类带悬念的连续叙事。首图建立动作方向，中段负责延伸，尾图给出终点回应，支持复用中段画面，也支持逐张指定素材。

## 交付内容与自动核验

每次运行都会写入一个独立的新输出目录，默认开启覆盖保护，不会悄悄覆盖旧作品，最终交付四类文件：

- `images/01.png` 到 `20.png`：按上传顺序编号的独立 PNG 图片。
- `images.zip`：只包含独立切片图片的压缩包，便于传到手机端发布。
- `preview.html`：可在本地浏览器打开的横向预览页，支持调节高度和模拟间距检查衔接，但本地模拟不等同于手机客户端最终渲染效果。
- `manifest.json`：记录图片张数、像素宽高、文件摘要与检查状态。

为了确保成品质检可靠，仓库内置了 **13 项自动测试**，覆盖尺寸拦截、越界裁切、覆盖保护、文件篡改和 ZIP 一致性等场景；每次导出还会自动核对单图尺寸与可读性、压缩包条目是否完全匹配，以及连续切片重新拼回后是否与母图逐像素一致。

## 依赖说明、安装与第一个请求

本地运行需要 **Git**、**Python 3.9+** 和 **ImageMagick 7**，macOS 装有 Homebrew 时可直接执行 `brew install imagemagick`。导出脚本只在本地离线执行，但让 AI 绘制母图或素材会调用宿主助手的生图工具并消耗对应额度。

如果需要在最终导出时移除 EXIF、GPS 及来源信息，请另行安装独立的隐私技能 [sweety-image-privacy](https://github.com/threerocks/sweety-skills/tree/main/skills/sweety-image-privacy) 到同一技能目录；缺少该依赖时脚本仍会完成切片，但会在报告中明确标记隐私清理未完整执行。另外，画面内部自带的可见文字或水印不会被元数据清理移除。

将仓库克隆到 Codex 技能目录即可启用，若目录已存在请先确认内容，避免覆盖个人修改：

```bash
git clone https://github.com/threerocks/sweety-x-image-play.git \
  "${CODEX_HOME:-$HOME/.codex}/skills/sweety-x-image-play"
```

安装完成后新开对话，可以直接发送这段请求试跑第一组作品：

> 使用 $sweety-x-image-play，做一组云海列车连续切片。20 张独立图片，每张 76×1024，按顺序编号。给我单图、ZIP 和模拟预览，检查拼回后与母图一致。

手头已有现成横图时，也可以直接让它估算宽度能否整除并完成切片，或者按 `40×1920` 生成四根不同配色的独立窄条。

## 平台支持边界

截至 2026 年 11 月 13 日，X 时间线已可见二十图原帖，例如 [Crain1Art](https://x.com/Crain1Art/status/2121009306233438440) 与 [ripped1taliano](https://x.com/ripped1taliano/status/2121044139705778359) 的帖子；但 [X iOS 帮助页](https://help.x.com/en/using-x/x-ios-app) 与 [创建帖子 API 文档](https://docs.x.com/x-api/posts/create-post) 仍标明上限为 4 张，[图片发布帮助](https://help.x.com/en/using-x/posting-gifs-and-pictures) 也未写明全量开放。本工具仅在本地出图，未在客户端实测发帖，上传前请核对账号权限，并参照 [ALT 说明文档](https://help.x.com/en/using-x/add-image-descriptions) 标注图片序号。
